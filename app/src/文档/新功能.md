# 新功能API文档 - 第二版

## 1. 删除单条消息接口

### 接口概述
该接口允许用户删除单条指定的消息记录，支持删除用户自己发送的消息或AI角色的回复消息。

---

### 接口详情

**接口地址**: `DELETE /api/chat/delete_message`

**功能描述**: 根据消息ID删除单条消息

**请求头**:
```
Authorization: Bearer <token>
Content-Type: application/json
```

**请求参数**:
```json
{
  "message_id": "消息ID"
}
```

**参数说明**:
- `message_id` (必填): 要删除的消息ID，必须是有效的MongoDB ObjectId格式

---

### 响应示例

#### 成功响应
```json
{
  "code": 200,
  "message": "消息删除成功",
  "data": {
    "deleted_message_id": "507f1f77bcf86cd799439011",
    "character_id": "68b479a4c51416f4807ce388",
    "character_name": "梅樊",
    "deleted_message_type": "text",
    "deleted_sender": "user",
    "remaining_messages": 15
  }
}
```

**响应字段说明**:
- `deleted_message_id`: 已删除的消息ID
- `character_id`: 关联的角色ID
- `character_name`: 角色名称
- `deleted_message_type`: 删除的消息类型（text/meme/intro等）
- `deleted_sender`: 消息发送者（user/character）
- `remaining_messages`: 删除后剩余的消息数量

---

#### 1. 未提供认证token

```json
  "code": 15001,
  "message": "未提供有效的认证token",
  "data": null
}
```

#### 2. 无效的token
```json
{
  "code": 15002,
  "message": "无效的token",
  "data": null
}
```

#### 3. 消息ID未提供
```json
{
  "code": 15026,
  "message": "消息ID是必填项",
  "data": null
}
```

#### 4. 无效的消息ID格式
```json
{
  "code": 15021,
  "message": "无效的消息ID格式",
  "data": null
}
```

#### 5. 消息不存在或无权限
```json
{
  "code": 15022,
  "message": "消息不存在或无权限操作",
  "data": null
}
```

#### 6. 删除失败
```json
{
  "code": 15033,
  "message": "删除消息失败",
  "data": null

```

#### 7. 服务器错误
```json
{
  "code": 15099,
  "message": "服务器内部错误，请稍后重试",
  "data": null
}
```

---

### 使用说明

1. **权限验证**: 只能删除属于当前用户的消息
2. **自动更新**: 删除消息后会自动更新对话记录的最后消息
3. **消息类型**: 支持删除所有类型的消息（文本、表情包等）
4. **对话维护**: 
   - 如果删除的不是最后一条消息，对话记录保持不变
   - 如果删除的是最后一条消息，会自动更新为前一条消息
   - 如果删除后没有消息了，会使用角色的开场白作为最后消息

---

### 调用示例

#### cURL 示例
```bash
curl -X DELETE "https://your-api-domain.com/api/chat/delete_message" \
  -H "Authorization: Bearer YOUR_TOKEN_HERE" \
  -H "Content-Type: application/json" \
  -d '{
    "message_id": "507f1f77bcf86cd799439011"
  }'
```

#### JavaScript 示例
```javascript
async function deleteMessage(messageId) {
  try {
    const response = await fetch('https://your-api-domain.com/api/chat/delete_message', {
      method: 'DELETE',
      headers: {
        'Authorization': `Bearer ${token}`,
        'Content-Type': 'application/json'
      },
      body: JSON.stringify({
        message_id: messageId
      })
    });
    
    const result = await response.json();
    
    if (result.code === 200) {
      console.log('消息删除成功:', result.data);
      console.log(`剩余消息数: ${result.data.remaining_messages}`);
    } else {
      console.error('删除失败:', result.message);
    }
  } catch (error) {
    console.error('请求失败:', error);
  }
}

// 使用示例
deleteMessage('507f1f77bcf86cd799439011');
```

#### Python 示例
```python
import requests
import json

def delete_message(token, message_id):
    url = "https://your-api-domain.com/api/chat/delete_message"
    headers = {
        "Authorization": f"Bearer {token}",
        "Content-Type": "application/json"
    }
    data = {
        "message_id": message_id
    }
    
    response = requests.delete(url, headers=headers, json=data)
    result = response.json()
    
    if result['code'] == 200:
        print(f"消息删除成功")
        print(f"剩余消息数: {result['data']['remaining_messages']}")
        return True
    else:
        print(f"删除失败: {result['message']}")
        return False

# 使用示例
token = "YOUR_TOKEN_HERE"
message_id = "507f1f77bcf86cd799439011"
delete_message(token, message_id)
```

---

### 注意事项

1. **消息ID获取**: 消息ID可以从聊天记录接口 (`/api/chat/messages/<conversation_id>`) 中获取
2. **删除限制**: 只能删除属于当前登录用户的消息
3. **不可恢复**: 删除操作不可逆，请谨慎使用
4. **对话完整性**: 删除消息可能影响对话的连贯性，建议谨慎删除
5. **批量删除**: 如需删除多条消息，建议使用回溯接口 (`/api/chat/rollback_to_message`) 或清空接口 (`/api/chat/clear/<character_id>`)

---

### 与其他接口的区别

| 接口 | 功能 | 适用场景 |
|------|------|----------|
| `/api/chat/delete_message` | 删除单条消息 | 删除特定的某一条消息 |
| `/api/chat/rollback_to_message` | 回溯到指定消息 | 删除某条消息之后的所有消息 |
| `/api/chat/clear/<character_id>` | 清空角色聊天 | 清空与某个角色的所有聊天记录 |
| `/api/chat/clear-all` | 清空所有聊天 | 清空用户的所有聊天记录 |

## 2. 更新单条消息接口

### 接口概述
该接口允许用户更新单条消息的内容。

---

### 接口详情

**接口地址**: `PUT /api/chat/update_message`

**功能描述**: 根据消息ID更新消息内容

**请求头**:
```
Authorization: Bearer <token>
Content-Type: application/json
```

**请求参数**:
```json
{
  "message_id": "消息ID",
  "content": "新的消息内容"
}
```

**参数说明**:
- `message_id` (必填): 要更新的消息ID，必须是有效的MongoDB ObjectId格式
- `content` (必填): 新的消息内容，不能为空，最多500字

---

### 响应示例

#### 成功响应
```json
{
  "code": 200,

  "data": {
```

## 5. 综合角色列表接口优化

### 更新日期
2025-12-13

### 接口概述
优化了综合角色列表接口，新增支持按热度（popularity）排序功能，同时保留原有的随机获取功能。

---

### 接口详情

**接口地址**: `GET /characters/comprehensive`

**功能描述**: 获取综合角色列表，返回所有公开的角色，支持分页和多种排序方式

**认证方式**: 可选（携带 Token 可获取更多个性化信息）

---

### 请求参数

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| page | integer | 否 | 1 | 页码，从1开始 |
| limit | integer | 否 | 20 | 每页数量 |
| sort_by | string | 否 | created_at | 排序字段 |
| sort_order | integer | 否 | -1 | 排序顺序：-1降序，1升序 |
| include_unlimited | boolean | 否 | false | 是否包含无限制角色 |

---

### sort_by 支持的值

| 值 | 说明 | 推荐使用场景 |
|---|------|------------|
| `random` | 随机排序 | 发现新角色、推荐页面 |
| `popularity` | 按热度排序 | 热门榜单、最受欢迎 |
| `created_at` | 按创建时间排序 | 最新角色、时间线 |
| `updated_at` | 按更新时间排序 | 最近更新 |
| `name` | 按名称排序 | 字母顺序浏览 |

---

### 请求示例

```bash
GET /characters/comprehensive?sort_by=created_at&sort_order=-1&page=1&limit=20
```

#### 5. 最近更新的角色
```bash
GET /characters/comprehensive?sort_by=updated_at&sort_order=-1&page=1&limit=20
```

#### 6. 按名称字母顺序

### 业务逻辑说明

#### 1. 排序逻辑

**随机排序（sort_by=random）**：
- 使用 MongoDB 的 `$sample` 聚合管道
- 每次请求返回不同的随机结果
- 适合推荐和发现场景
- **注意**：随机模式下分页可能不连续

**字段排序（sort_by=其他值）**：
- 使用标准的 `find().sort()` 查询
- 支持升序（sort_order=1）和降序（sort_order=-1）
- 分页结果稳定连续

#### 2. 热度（popularity）计算

- 热度值 = 添加该角色为好友的用户数量
- 每次有用户添加角色时 +1
- 每次有用户移除角色时 -1
- 热度值越高，角色越受欢迎

#### 3. 筛选条件

接口只返回满足以下条件的角色：
- `is_public: true` - 公开角色
- `is_active: true` - 激活状态
- `review_status: "approved"` - 审核通过
- `deleted_by_creator: false` - 未被创建者删除

#### 4. 用户个性化信息

如果请求携带有效的 Authorization Token，返回数据会包含：
- `in_chat_slots` - 该角色是否在用户的聊天槽位中
- `is_my_character` - 该角色是否是用户自己创建的
- `conversation_id` - 与该角色的会话ID（如果存在）
- `permanent_memory_enabled` - 是否为该角色开启了永久记忆

### 业务逻辑说明

#### 1. 消息发送时机

**用户注册**:
```python
# 注册成功后自动发送欢迎消息
Notification.create_system_notification(
    mongo=mongo,
    user_id=user_id,
    title="欢迎来到深触AI",
    content=f"欢迎您，{username}！开始与AI角色的奇妙对话之旅吧～"
)
```

**邀请奖励**:
```python
# 被邀请人注册成功后，给邀请人发送奖励通知
Notification.create_invitation_reward_notification(
    mongo=mongo,
    user_id=inviter_id,
    invitee_name=username,
    reward_amount=100
)
```

**关注通知**:
```python
# 用户A关注用户B时，给用户B发送通知
Notification.create_follow_notification(
    mongo=mongo,
    user_id=target_user_id,
    follower_id=current_user_id,
    follower_name=current_user_name,
    follower_avatar=current_user_avatar
)
```

**角色审核**:
```python
# 管理员审核角色后，给创建者发送通知
Notification.create_character_review_notification(
    mongo=mongo,
    user_id=creator_id,
    character_id=character_id,
    character_name=character_name,
    review_status="approved",  # 或 "rejected"
    reject_reason=None  # 拒绝时提供原因
)
```

**购买成功**:
```python
# 购买会员成功后发送通知
Notification.create_purchase_notification(
    mongo=mongo,
    user_id=user_id,
    item_name="银钻会员",
    amount=2000,
    currency_type="fairy_jade"
)
```

#### 2. 小红点逻辑

- 实时查询未读消息数量
- 使用数据库索引优化查询性能
- 前端定时轮询或在关键操作后更新

#### 3. 消息保留策略

- 所有消息永久保留
- 用户可以手动删除单条消息
- 用户可以一键清空所有消息
- 已读消息和未读消息都会保留

### 性能优化建议

1. **数据库索引**: 必须创建复合索引以优化查询性能
2. **分页查询**: 限制每页最大100条，避免一次性加载过多数据
3. **缓存策略**: 可以在Redis中缓存未读数量，减少数据库查询
4. **定期清理**: 可以定期清理超过90天的已读消息（可选）
